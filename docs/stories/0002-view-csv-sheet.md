# Story-0002:在浏览器里查看 CSV 表格

- 关联:[RFC-0003](../rfcs/0003-csv-canvas-grid.md)、[Spec-0002](../specs/0002-csv-grid-render.md)

## 用户故事

> 作为一个需要临时查看数据文件的人,
> 我希望**把 CSV 拖进浏览器就能像 Excel 一样浏览它**,
> 这样我不必为了看一眼几十万行的导出文件而打开笨重的桌面软件,
> 也不用担心把数据传到某个在线服务上 —— 整个过程都在本地完成。

## 验收场景

### 场景 1:打开一个普通 CSV

- **Given** 我在「表格」页
- **When** 我上传一个逗号分隔的 UTF-8 CSV
- **Then** 我看到带行号(1、2、3…)与列名(A、B、C…)的表格
- **And** 单元格内容与原文件逐格一致
- **And** 页面显示识别出的编码、分隔符、行列数与解析耗时

### 场景 2:内容里有逗号、引号和换行

- **Given** 某个字段是 `"上海,中国"`,另一个字段里有 `""` 转义引号,还有字段内嵌换行
- **When** 我打开它
- **Then** `上海,中国` 完整显示在**一个**单元格里
- **And** 转义引号显示为一个 `"`
- **And** 内嵌换行的字段仍占一行,换行处显示为空格

### 场景 3:中文 CSV 是 GBK 编码

- **Given** 文件是 Excel 另存的 GBK 编码 CSV(没有 BOM)
- **When** 我打开它
- **Then** 中文正常显示而不是乱码
- **And** 页面标明「编码 GBK」

### 场景 4:分隔符不是逗号

- **Given** 文件用分号(或制表符、竖线)分隔
- **When** 我打开它
- **Then** 列被正确切分
- **And** 页面标明识别出的分隔符及「自动识别」

### 场景 5:浏览一个 50 万行的大文件

- **Given** 一个约 40 MB、50 万行 × 12 列的 CSV
- **When** 我上传它
- **Then** 一秒内就能看到内容,期间界面不卡死
- **And** 我用滚轮上下翻、左右翻,画面流畅跟手
- **And** 无论翻到多少行,行列头始终固定可见

### 场景 6:放大看清楚一点

- **Given** 表格已经显示出来
- **When** 我按住 Ctrl(⌘)滚动滚轮
- **Then** 表格以**鼠标指针所在的单元格为中心**缩放,那个格子不会跑掉
- **And** 放大后文字依然清晰不发虚
- **And** 此时点击某个单元格,选中的正是我点的那一格

### 场景 7:用键盘浏览

- **Given** 表格已获得焦点
- **When** 我按方向键 / PageDown / Ctrl+End
- **Then** 选区随之移动,并自动滚动到可见位置
- **And** 状态栏显示当前单元格地址(如 `C227759`)与它的完整内容

### 场景 8:某个单元格文字太长

- **Given** 某个单元格的文字远超列宽
- **When** 表格渲染出来
- **Then** 文字被裁剪并以省略号结尾,**不会溢出到相邻列**
- **And** 点选该单元格后,状态栏能看到完整内容

### 场景 9:上传了一个空文件

- **Given** 一个 0 字节的文件
- **When** 我上传它
- **Then** 我看到「文件内容为空,没有可显示的数据」
- **And** 页面没有崩溃,我可以直接再选一个文件

### 场景 10:上传了一个不是文本的文件

- **Given** 一个图片或其它二进制文件(哪怕扩展名是 `.csv`)
- **When** 我上传它
- **Then** 我看到「这看起来不是文本文件…」的提示,而**不是**一屏乱码
- **And** 提示里带排查编号,便于我报障时说明

### 场景 11:文件超出上限

- **Given** 行数超过 200 万的 CSV
- **When** 我打开它
- **Then** 我仍能看到前 200 万行
- **And** 页面明确标注「已达上限,超出部分未显示」,我不会误以为文件就这么大
