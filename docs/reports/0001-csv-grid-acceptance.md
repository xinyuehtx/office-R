### 过程中发现并修复的九个真实缺陷

记录于此,因为它们都是「测试没覆盖到、只有跑真实浏览器才暴露」的问题:

1. **单元格内容整体错位**:`CellWindow.ends` 用的是 UTF-8 字节偏移,而 JS 的
   `String.slice` 按 UTF-16 码元计数,含中文时全盘错位。
   → 内核改为输出 UTF-16 码元偏移,并补上断言这一点的单测。
   (第一次现象出现的直接原因是**改了内核却没重建 WASM**,已在 AGENTS.md 与
   架构文档中写明这条坑。)
2. **二进制文件被当成 CSV 渲染成乱码**:单字节编码能把任意字节硬解成字符。
   → 内核新增 `CsvError::NotText`,按 NUL 与不可打印字符密度拦截。
3. **解析失败被重试了两遍**:Worker 返回的解析错误触发了「降级到主线程」逻辑,
   日志里出现两条同样的错误,大文件还会白白卡一次 UI。
   → 区分「Worker 不可用」与「解析失败」,只有前者才降级。
4. **画布高度不随窗口变化**:宽度自适应正常,高度却固定 —— 从 `.app` 到
   `.sheet__viewport` 的高度链断了(flex 子项缺 `min-height: 0`)。
   canvas 不像 DOM 会按内容长高,容器必须给出确定高度。
   → 表格页补上完整高度链,并实测三档窗口尺寸确认宽高都跟着变。
5. **鼠标无法横向滚动**(用户反馈):只透传了 `deltaX`,触控板可用,而普通鼠标
   根本发不出 `deltaX`;Shift+滚轮被当成纵向滚动。
   → 新增 `grid/input.ts` 把滚轮语义抽成纯函数并单测 12 项:Shift+滚轮转横向,
   且平台已给出 `deltaX` 时不重复转换(否则横滚两倍)。
6. **非整数 dpr 下画面发虚**(用户反馈):后备像素按 `round(css × dpr)` 取整,
   但显示尺寸仍用原始的小数 CSS 宽度 —— 1151 × 1.25 = 1438.75,取整成 1439 后
   位图与屏幕像素比变成 1.000174,浏览器就会重采样整块画布。
   浏览器缩放与 125%/150% 显示缩放下必然触发。
   → 改为后备像素与显示尺寸**同源换算**(向下取整到整设备像素,再反推显示尺寸),
   比值从 2.9e-4 收敛到 ≤5e-6,并加 8 组 dpr × 容器尺寸的回归用例。

另有一处显示质量问题:列宽估算按 8 px/半角单位偏窄,导致「明明放得下的 5 位数字
被打上省略号」。实测该字体下数字最宽 8.29 px、大写字母 8.7 px,遂改为 9 px 并在
常量处记录实测依据。

7. **瓦片边缘会画成空白**(改造中被测试逼出来):单元格取数仍按「可见区域」算,
   而瓦片比可见区域大一圈 —— 余量那圈的单元格不在缓存里,会渲染成空白,
   一旦 GPU 平移露出来就穿帮。行高变小(缩小视图)时必然触发。
   → 新增 `rangeForContentRect`,改为**按瓦片取数**;并把「判断缓存命中」的范围
   与「实际去取」的范围分开,后者更大,好让重锚还能命中缓存走增量。
8. **内容比视口小时退化为每帧全量重绘**:`tileCovers` 要求瓦片盖住整个可见区域,
   可窄表格右侧本来就是空白,永远盖不住 → 判定失败 → 每帧重画。
   → 覆盖判定与内容边界求交。
9. **首帧取了两次数**:改造时忘了删掉旧的按可见区域取数的调用,和新的按瓦片取数
   叠在一起,第一次取的范围还偏小,必然再取一次。
   → 删掉旧调用;`windowFetches` 的断言把它钉住了。

> 第 5、6 条是交付后由人工审查发现的,第 7~9 条是分层改造时被自己的测试逼出来的。
> 前者说明:**自动化测试断言的是我写下的期望,我没想到的事情它不会替我想到** ——
> 横向滚动只覆盖了 `deltaX`,像素对齐压根没有断言。后者说明反过来也成立:
> 一旦把「每层各画了几次」变成可断言的事实,藏在架构里的浪费就藏不住了。

## 五、已知限制

1. **列宽是估算值**:内核按「半角字符数」度量,前端用实测最坏情况(9 px/单位)换算。
   精确度量需要遍历全部单元格调用 `measureText`,百万行下不可接受。
   代价是整列都由 `W`/`M` 这类超宽字符组成时仍可能出现省略号 ——
   此时可点选单元格在状态栏查看完整内容。列宽拖拽调整尚未实现。
2. **上限**:256 MiB / 200 万行 / 16384 列,超出按截断处理并在界面标注。
3. **交互面仍薄**:没有区域选择与复制、列排序筛选、查找。
4. **xlsx 表格视图未接入**:本期范围只含 CSV;接入路径已在架构文档「扩展边界」写明
   (新增解析入口产出 `Sheet`,视图层复用 `SheetHandle` 接口,预期一行不改)。
5. **分层的显存代价**:三张画布各占一块纹理,单元格层还比视口大一圈。
   1400×900 视口、dpr 2 时合计约 40 MB 显存。这是拿显存换绘制开销的自觉选择,
   瓦片余量(256 设备像素)是这笔交易的调节旋钮。
6. **WASM 体积 1.5 MB**:主要来自仍被链接的 `calamine` / `docx-rs`(供文档与演示页使用),
   与本期改动无关;若要瘦身可按页面拆分 WASM 产物。
